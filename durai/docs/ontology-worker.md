# Ontology-bound coding worker

## Effective policy

New generic installations use durai.software-generation version 2. Version 1 remains immutable and available for historical records. Version 2 permits only ASD-STE100 sample walkthrough comments. This includes docstrings used as comments. Each function must have its own walkthrough. The gate rejects other comments and common rationale wording. A human must still review full language compliance and sample accuracy.

The resolver loads the exact generic policies and authorized application knowledge from the binding. It excludes memory records and protected evaluator cases. The contract contains policy text, pack digests, binding revision, domain rules, permitted files, and permitted tools. A changed current binding invalidates the contract before dispatch and before readiness advances.

The qualified runtime still supports the signed-lot position domain. Free-text ontology records do not add new executable adapters. New domains require explicit domain validation and acceptance goals.

## Worker boundary

The worker exposes read_file, edit_file, and write_file. It has no task, execute, search, delete, or planning tool. A dedicated harness profile disables the default subagent. A model wrapper refuses undeclared tool calls.

File permissions allow reads and writes only for /workspace/program.py. All other paths are denied. The adapter checks the complete file set, directory set, and protected file digests after dispatch. It rejects symlinks and forbidden comments before a candidate is returned.

## Repair and generation

Generation resolves the contract from its application binding. Model repair accepts --binding on the repair command and retains it in factory state. A resumed factory cannot replace that binding. Without one, it creates a separate canonical version 2 repair binding. It does not replace an existing binding.

Both paths record ordered readiness, a runnable baseline, an independent business failure, and implementation permission. Both evaluate the candidate through a protected suite. A proposal records its contract digest. A repair registration also records its engineering run ID. Passing results wait for release review. Business failures remain available to the existing bounded factory retry flow.

## Version 2 bindings

Use foundation-generic-v2 for new generic-only generation. When the existing exchange pack is available, use foundation-exchange-v2 for trading generation. The qualification receipt lists created bindings and exact pack references. Existing bindings, registered source, approvals, and target versions are preserved.

From the durai folder, run:

```powershell
python local.py greenfield --binding foundation-generic-v2
```

For a model repair, run python local.py repair --binding foundation-exchange-v2. Add --model to the greenfield command to use the configured coding provider. The same contract and protected evaluation apply.

## Limits

This change closes the four reviewed local foundation gaps. It does not qualify general planning or critic models. Shared request cost budgets and broader agent audit remain separate work. Historical source and evidence retain their original comments. New candidate output must pass the version 2 comment gate.
